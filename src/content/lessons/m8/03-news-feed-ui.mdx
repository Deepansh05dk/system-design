<Callout type="problem">
Design the frontend for a social media news feed: an endless scroll of posts with text, images and videos, likes and comments, new posts arriving while you read, used by people on cheap Android phones with flaky 3G and on fast laptops. It must feel instant, never jump around, and work with a screen reader.
</Callout>

## R: Requirements

**Functional:** view an infinite feed; each post has author, text, media, like/comment/share; like a post; open comments; create a post; see that new posts are available.

**Non-functional:** fast initial load (LCP < 2.5 s on mid-range mobile), smooth 60 fps scrolling, works on slow networks, accessible (keyboard + screen reader), handles thousands of loaded posts without slowing down.

## D: Data model (client)

```ts
type Post = { id: string; authorId: string; text: string; media: Media[];
              likeCount: number; likedByMe: boolean; commentCount: number; createdAt: string };
type User = { id: string; name: string; avatarUrl: string };
type FeedState = { postIds: string[]; nextCursor: string | null; status: 'idle'|'loading'|'error';
                   pendingNewIds: string[] };
```

Server data → cached & normalized. UI state (open comment boxes, composer draft) → local component state; draft also saved to `localStorage` so a refresh doesn't lose it.

## I: Interface

```http
GET  /feed?cursor=<opaque>&limit=20  → { posts: [...with author], nextCursor }
POST /posts                          { text, mediaIds }  Idempotency-Key: …
POST /posts/:id/like  |  DELETE /posts/:id/like
GET  /feed/stream (SSE)              → event: new_posts  data: { ids: [...] }
```

Why cursor pagination? New posts constantly arrive at the top; offset pagination would show duplicates (Module 4).

## O: Optimizations & deep dives

### Virtualization

<VirtualListSim />

Only render what's on screen (react-window, TanStack Virtual). With variable-height posts, measure items after render and cache heights. Keep a few items of overscan for smooth scrolling. Restore scroll position when the user navigates back.

### Infinite scroll mechanics

- An **IntersectionObserver** sentinel near the end triggers loading the next page (prefetch ~1–2 screens ahead).
- Guard against duplicate requests (in-flight flag), and dedupe posts by ID.
- Show skeletons while loading; an inline "Retry" on error (don't blank the whole feed).

### Optimistic likes

Update `likedByMe` and `likeCount` instantly; send the request; on failure roll back and show a toast. Rapid double-taps: debounce or send the final state (`PUT like: true/false`, idempotent) instead of toggling.

### Media performance

Responsive images (`srcset`), lazy loading below the fold, fixed aspect-ratio boxes to prevent layout shift (CLS), blur-up placeholders, videos autoplay muted only when visible (IntersectionObserver), pause when scrolled away.

### Network resilience

Cache the last feed (IndexedDB) to show something instantly on open / offline; queue actions (likes, posts) while offline and replay them when back (with idempotency keys).

### Accessibility

Use a semantic `<article>` per post inside a `role="feed"` container (with `aria-busy` while loading), meaningful alt text, visible focus, keyboard shortcuts (j/k to move between posts), and announce "12 new posts" via a polite live region. Virtualized lists must keep focus stable when rows unmount.

<Takeaways>
- Normalize server data; feed = ordered **list of IDs**; memoize items.
- **Cursor pagination + IntersectionObserver** for infinite scroll; dedupe by ID.
- **Virtualize** long lists; reserve media space to avoid CLS; lazy-load media.
- **Optimistic updates** with rollback; **“N new posts”** pill instead of shifting content.
- Plan **offline** (IndexedDB cache, queued actions) and **accessibility**.
</Takeaways>
